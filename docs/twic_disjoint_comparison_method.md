# Disjoint comparison of four checkpoints: method and result contract

This document defines the method for TWIC issues 1662–1667. The project owner
confirmed that these issues were absent from all four training runs. The
evaluation is implemented in `analysis/ply_comparison/evaluate.py`; the charts
and a run-specific `README.md` are generated by
`analysis/ply_comparison/plot_results.py`.

## Models

| CSV `model_id` | Checkpoint | Family |
|---|---|---|
| `encoder_baseline` | `chess_encoder_seq_v1_07_03_FINAL.pt` | Encoder |
| `encoder_balanced` | `chess_encoder_seq_balanced_v1.best.pt` | Encoder |
| `decoder_baseline` | `chess_llm_decoder_v12.pt` | Decoder |
| `decoder_balanced` | `chess_llm_decoder_balanced_v1_final.pt` | Decoder |

All metrics use the same decisions from the same games, always the board
before the recorded move. The primary comparison is balanced minus baseline
within each family. Absolute-ply bands are `0_20`, `20_40`, `40_60`,
`60_80`, `80_100`, and `100_plus`; lower bounds are inclusive and upper
bounds exclusive. A secondary summary uses relative game-progress quintiles.

## Metrics

The target is the complete human move in UCI, including any promotion suffix.
At each position, `top1_correct` is 1 if the model's legal greedy move matches
the target and 0 otherwise. For `top5_correct`, place the greedy choice first
and complete the list with the four highest-probability remaining legal UCI
moves, without duplicates. This includes the encoder's promotion fallback.
Band accuracies are averages over **decisions**, not averages of game-level
percentages. The CSV also includes equal-game-weighted accuracy as a
sensitivity analysis.

`nll_legal = -ln p(target | legal UCI moves)`. The probability is normalized
only over moves legal in the current position. Band-level legal perplexity is
`exp(mean nll_legal)`, not the mean of per-move perplexities. The paired
differences `delta_accuracy_top1` and `delta_nll_legal` are balanced minus
baseline. A positive accuracy difference favors balanced; a negative NLL
difference favors balanced. A 95% interval is computed by resampling **whole
games** with replacement, using the same draw for both checkpoints.

The decoder masks illegal and special-token logits before normalizing. The
encoder normalizes logits across legal `(from,to)` pairs and, for promotion
pairs, divides that pair's probability among its legal promotions using the
`promo_head`. Encoder top-1 follows the exact greedy and fallback behavior
in `sample_moves()`; its NLL uses the explicit probabilistic UCI distribution.
The per-move CSV also records the encoder's historical `(from,to)` correctness.

These metrics measure agreement with the recorded move. A different move can
also be strong. This analysis alone does not measure chess move quality or
establish internal-state drift. Context probes, model-action trajectories,
and Stockfish move-quality analysis remain separate tests in the plan.

## Data and provenance

The dataset builder's `--all-games-in-range` mode includes all qualifying
games from issues 1662–1667, marks each with a `TWICIssue` PGN header, and
removes duplicate complete games. Filtering requires valid nonempty
standard-chess games, no null moves, both player Elos at least 1600, and the
`classic` category inferred from the `Event` header. The category is a
heuristic, not proof of clock settings. The builder report records per-issue
download hashes and filtering counts. The evaluator manifest records hashes
for the PGN, offset index, tokenizer, and four checkpoints, plus versions,
sample counts, date range, and the Git revision.

`analysis/ply_comparison/audit_corpus.py` checks every indexed game's `Date`
and `TimeControl` header and writes
`processed_games/eval/twic_1662_1667_corpus_audit.json`. In the current corpus, **21,309 of 44,049
games (48.4%) explicitly have a 180- or 300-second control**, despite the
`classic` category name. The primary cohort therefore mixes time controls;
interpret results as an event-name-selected TWIC sample, not classical chess.
All 44,049 dates parse as 2026 dates, but several games predate their issue
by weeks or months. TWIC issue is the provenance key, not a game-date rule.

The evaluator reads each recorded game once and predicts every accepted ply.
For the decoder, its input is `[BOS, preceding UCI moves]` and the matching
moved-piece stream, truncated to the last 256 tokens. A single causal pass
can score all prefixes before truncation; later plies use sliding windows.
For the encoder, each input is the explicit board and metadata before the
target move. Both models are evaluated in inference mode with strict
checkpoint loading.

## CSVs consumed by the chart script

`bucket_summary.csv` has one row per model and absolute-ply band (24 rows).
The chart script requires the first seven columns; additional columns give
legal perplexity and equal-game-weighted sensitivity estimates.

```csv
model_id,bucket,n_games,n_plies,accuracy_top1,accuracy_top5,nll_legal,perplexity_legal,accuracy_top1_equal_game,nll_legal_equal_game
encoder_baseline,0_20,1200,21000,0.50,0.78,1.72,5.5845,0.49,1.74
```

`paired_deltas.csv` has one row per family and absolute-ply band (12 rows).
Intervals and differences are proportions or NLL values, not percentages.

```csv
family,bucket,n_games,n_plies,delta_accuracy_top1,ci_low_accuracy_top1,ci_high_accuracy_top1,delta_nll_legal,ci_low_nll_legal,ci_high_nll_legal
encoder,0_20,1200,21000,0.02,0.01,0.03,-0.05,-0.07,-0.03
```

The numeric rows above illustrate the format and **are not project results**.
All four model rows in a band must have the same sample counts. The reported
paired difference must equal the difference between model means, up to
rounding tolerance. Top-5 accuracy cannot be below top-1. The chart script
rejects missing or inconsistent rows.

`relative_summary.csv` uses the same summary columns and bands `q0_20`,
`q20_40`, `q40_60`, `q60_80`, and `q80_100`. The relative position is
`ply / game_plies`. It is secondary and is not mixed with absolute-ply
figures. `per_move.csv` includes game/ply identifiers, issue, date, player
Elos, pre-move FEN, target and chosen UCI moves, legal-move count, context
length, top-1/top-5 correctness, and target probability/NLL.

## Commands and outputs

Build the corpus from the repository root:

```powershell
.venv/Scripts/python.exe -m utils.dataset_by_category.twic_category_builder `
  --all-games-in-range --categories classic `
  --start-week 1667 --lower-week 1662 --min-elo 1600 `
  --output-dir processed_games/eval --prefix twic_1662_1667
```

Audit the PGN headers:

```powershell
.venv/Scripts/python.exe -m analysis.ply_comparison.audit_corpus
```

Evaluate and generate charts:

```powershell
.venv/Scripts/python.exe -m analysis.ply_comparison.evaluate `
  --output-dir outputs/twic_1662_1667
```

The evaluator writes `per_move.csv`, `bucket_summary.csv`,
`paired_deltas.csv`, `relative_summary.csv`, and `manifest.json`, then calls
the chart script. The chart script writes `accuracy_by_ply.svg`,
`nll_by_ply.svg`, `delta_accuracy_by_ply.svg`, `delta_nll_by_ply.svg`, and a
run-specific `README.md` under `figures/`. The chart script uses only
Python's standard library.

For a quicker end-to-end analysis on a CPU, select the same number of games
from each issue with SHA-256 ranking of complete indexed PGN records:

```powershell
.venv/Scripts/python.exe -m analysis.ply_comparison.evaluate `
  --sample-games-per-issue 10 `
  --output-dir outputs/twic_1662_1667_sample_10
```

This is an exploratory sample. The manifest distinguishes a finished sampled
run (`complete=true`, `full_corpus=false`) from the full evaluation and records
the selection method and counts. Small sampled runs have wide game-level
intervals; use the full command above for the planned primary analysis.

During evaluation, progress is printed every 100 processed games with the
completed fraction, accepted and excluded counts, processing rate, and an ETA.
For example: `Progress: 100/44049 games (0.23%), 100 processed, 0 excluded;
ETA 123.4 min`.

Regenerate the charts from either run's CSVs:

```powershell
.venv/Scripts/python.exe -m analysis.ply_comparison.plot_results `
  --summary outputs/twic_1662_1667/bucket_summary.csv `
  --deltas outputs/twic_1662_1667/paired_deltas.csv `
  --output-dir outputs/twic_1662_1667/figures
```

The run-specific README explains the metrics and figures, reports sample
sizes and paired intervals, and records SHA-256 hashes of the two summary
CSVs. The manifest is the authoritative record of inputs and execution.
